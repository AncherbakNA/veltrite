# GitHub Sync

Каждый пользователь подключает **свой отдельный приватный репозиторий**. Репозиторий с исходниками Veltrite и репозитории заметок не связаны между собой.

## Первое устройство

1. Создайте пустой приватный репозиторий, например `veltrite-sync`.
2. В GitHub создайте fine-grained personal access token. Укажите только этот репозиторий и разрешение **Contents: Read and write**. Административные разрешения не нужны.
3. Откройте **Настройки → GitHub Sync**, введите `владелец/репозиторий` и токен.
4. Нажмите **Подключить**. Для нового хранилища ключ будет создан на устройстве.
5. Сохраните ключ восстановления отдельно от репозитория, например в менеджере паролей.
6. Выполните первый обмен. Автоматическую синхронизацию можно включить после сохранения ключа.

GitHub App Device Flow также реализован. Для кнопки входа издатель должен зарегистрировать собственный GitHub App и указать его публичный Client ID при сборке. До этого вход по токену полностью доступен. Client Secret и ключи издателя не встраиваются в клиент.

## Второе устройство

Подключите тот же приватный репозиторий и введите **ключ восстановления с первого устройства**. Вход в GitHub выполняется для каждого устройства отдельно. Токен и ключ сохраняются зашифрованными через системные средства Electron safeStorage — Keychain на macOS и DPAPI на Windows.

## Что передаётся

- Заметки, вложения, `.canvas`, `.base` и папки, включая пустые.
- Переносимые настройки хранилища, пути папок внутри него и закладки.

Локальная история, корзина, кэши, список открывавшихся папок, абсолютные пути, GitHub-токен, ключ восстановления и скрытые служебные каталоги в репозиторий синхронизации не отправляются. Код сторонних плагинов не пересылается и не запускается автоматически.

## Шифрование и конфликты

Каждый изменённый файл шифруется отдельно AES-256-GCM с новым случайным nonce и ключом, полученным через HKDF. Имена и структура находятся в зашифрованном манифесте. Репозиторий и путь файла привязаны к шифротексту через дополнительные аутентифицируемые данные.

Перед записью выполняется трёхстороннее сравнение: последнее принятое состояние, локальные файлы и состояние GitHub. Независимые правки объединяются. Если один файл изменён на двух устройствах, удалённая версия остаётся на исходном пути, а локальная сохраняется рядом с суффиксом `конфликт`. Изменение, конфликтующее с удалением, тоже сохраняется отдельным файлом.

Запись манифеста и объектов публикуется одним Git-коммитом. Обновление ветки выполняется без `force`. При гонке изменений локальные файлы не заменяются неподтверждённым результатом. При повторном обмене состояние считывается заново.

## Ограничения

В этой версии: до 32 МиБ на файл, до 512 МиБ содержимого одного хранилища и до 50 000 записей. Это ограничения реализации Veltrite. GitHub также применяет собственные ограничения API и репозиториев; большие и часто меняющиеся видео плохо подходят для такого хранения.

Автоматический обмен работает только при запущенном приложении, по умолчанию выключен и после включения выполняется каждые пять минут. Перед первым использованием на личных данных рекомендуется проверить обмен на отдельном тестовом репозитории.

Отключение устройства не удаляет заметки с диска или данные GitHub. Удаления передаются при последующей синхронизации и доступны в локальной корзине на принимающем устройстве. Синхронизация не заменяет независимую резервную копию.
