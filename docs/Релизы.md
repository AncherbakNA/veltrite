# Подготовка релиза

## Локальная сборка

Запустите `pnpm dist:mac` для Apple Silicon либо `pnpm dist:win` для Windows x64. Рабочая копия и установщики создаются снаружи репозитория. На Mac возможна сборка Windows-пакета, но она не заменяет запуск на Windows.

Сборка на Mac подписывается ad-hoc без обращения к личным сертификатам издателя. Developer ID, нотарификация Apple и Authenticode Windows пока не подключены. Для массового распространения их нужно оформить отдельно.

## GitHub Actions

Обычные push и pull request запускают проверки типов и файлов на macOS и Windows. Интерфейсные сценарии выполняются на обеих платформах.

Тег `v<версия>` запускает сборки Mac ARM64, Mac x64 и Windows x64. Версия тега должна совпадать с `package.json`. После успеха создаётся **черновик** GitHub Release с установщиками и SHA-256. Публикация черновика выполняется после приёмки пакетов.

Ветки `codex/**` и ручной запуск проходят ту же нативную приёмку без публикации установщиков. На каждой платформе проверяется установленный пакет; Windows дополнительно проходит установку 0.2.1, обновление текущим EXE, настоящее автообновление локальным тестовым кандидатом и удаление с сохранением данных. Установщики загружаются как артефакты только для тегов; отчёты — для всех прогонов.

Перед созданием черновика `scripts/release-files.mjs` объединяет шесть установочных файлов, создаёт `latest.yml`, `latest-mac.yml` для обеих архитектур и контрольные суммы файлов, лент и blockmap. Одинаковые имена с разным содержимым останавливают публикацию.

## Вход и обновления

Официальный публичный репозиторий релизов — `AncherbakNA/veltrite`. Его можно переопределить при сборке через `VELTRITE_RELEASE_REPOSITORY=owner/repository`. GitHub Sync использует отдельное подключение пользователя.

Windows загружает обновление с проверкой SHA-512 и запускает NSIS после явного нажатия кнопки и сохранения черновиков. Обычный выход не устанавливает обновление. Mac без Developer ID использует ручную замену из DMG. Подключение сертификатов и нотарификации описано в [инструкции](Установка-и-обновления.md); включённая подпись без секретов останавливает сборку.

Для входа через браузер зарегистрируйте **собственный GitHub App**:

1. Разрешите Device Flow.
2. Дайте разрешение Contents: Read and write.
3. Ограничьте установку выбранными репозиториями.
4. Укажите публичный Client ID в переменной репозитория `VELTRITE_GITHUB_CLIENT_ID`.

Client Secret, приватные ключи приложения и токены пользователей в сборку не добавляются. Пока GitHub App не зарегистрирован, пользователь подключается fine-grained токеном.

Описание следующего релиза редактируется в `Описание-релиза.md`. Нативные сценарии используют временные профили и заметки; они не изменяют пользовательские установки.
