# Подготовка релиза

## Локальная сборка

Запустите `pnpm dist:mac` для Apple Silicon либо `pnpm dist:win` для Windows x64. Рабочая копия и установщики создаются снаружи репозитория. На Mac возможна сборка Windows-пакета, но она не заменяет запуск на Windows.

Сборка на Mac подписывается ad-hoc без обращения к личным сертификатам издателя. Developer ID, нотарификация Apple и Authenticode Windows пока не подключены. Для массового распространения их нужно оформить отдельно.

## GitHub Actions

Обычные push и pull request запускают проверки типов и файлов на macOS и Windows. Интерфейсные сценарии выполняются на обеих платформах.

Тег `v<версия>` запускает сборки Mac ARM64, Mac x64 и Windows x64. Версия тега должна совпадать с `package.json`. После успеха создаётся **черновик** GitHub Release с установщиками и SHA-256. Публикация черновика выполняется после приёмки пакетов.

Workflow также можно запустить вручную: тогда он создаст артефакты без релиза.

## Вход и обновления

`VELTRITE_RELEASE_REPOSITORY=owner/repository` задаёт публичный репозиторий релизов для проверки обновлений. В Actions он берётся из текущего репозитория только при публичной видимости. Для приватного репозитория проверка обновлений отключена; установщики доступны через GitHub Releases после входа в GitHub. Обновление сейчас открывает страницу установщика; автоматическая замена приложения ещё не реализована.

Для входа через браузер зарегистрируйте **собственный GitHub App**:

1. Разрешите Device Flow.
2. Дайте разрешение Contents: Read and write.
3. Ограничьте установку выбранными репозиториями.
4. Укажите публичный Client ID в переменной репозитория `VELTRITE_GITHUB_CLIENT_ID`.

Client Secret, приватные ключи приложения и токены пользователей в сборку не добавляются. Пока GitHub App не зарегистрирован, пользователь подключается fine-grained токеном.

Описание следующего релиза редактируется в `Описание-релиза.md`. Автоматические проверки не заменяют ручную приёмку установки и обновления на Windows.
