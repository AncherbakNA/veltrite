# Установка и обновления

Сборки: Mac с Apple Silicon (ARM64), Mac с Intel (x64), Windows x64. Установщики и `SHA256SUMS.txt` находятся в GitHub Releases.

На Mac откройте DMG и перенесите Veltrite в «Программы». На Windows запустите EXE и выберите папку установки. Заметки хранятся отдельно от приложения. Деинсталлятор Windows сохраняет профиль и хранилища.

## Обновление из приложения

Откройте «Настройки → О приложении → Проверить обновление». На Windows новая версия загружается после нажатия «Загрузить». Контрольная сумма SHA-512 проверяется перед установкой. «Перезапустить и обновить» сначала сохраняет открытые черновики, затем запускает NSIS и открывает новую версию. Установка при обычном закрытии приложения отключена. Во время записи аудио нужно сначала завершить запись и дождаться её сохранения.

Без Developer ID на macOS кнопка открывает страницу релиза: скачайте новый DMG и замените приложение. Нативное автоматическое обновление Mac включается только в сборках с подписью издателя и нотарификацией. Сейчас сертификатов издателя нет; Mac использует локальную ad-hoc подпись целостности, Windows собирается без подписи издателя.

`latest.yml` содержит Windows-установщик, `latest-mac.yml` — ZIP обеих архитектур Mac. Скрипт `scripts/release-files.mjs` собирает эти ленты из окончательных файлов и добавляет их вместе с blockmap в `SHA256SUMS.txt`. Пакеты не публикуются до завершения нативной приёмки.

## Подключение подписи в GitHub Actions

Секреты задаются в настройках репозитория, никогда в исходниках. Режим строгий: включённая подпись без необходимых секретов останавливает сборку.

| Платформа | Variables | Secrets |
| --- | --- | --- |
| Mac | `VELTRITE_SIGNED_MAC=1` | `MAC_CERTIFICATE_P12` (base64 P12), `MAC_CERTIFICATE_PASSWORD` |
| Нотарификация через Apple ID | — | `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` |
| Нотарификация через API вместо Apple ID | — | `APPLE_API_KEY_BASE64` (P8), `APPLE_API_KEY_ID`, `APPLE_API_ISSUER` |
| Windows | `VELTRITE_SIGNED_WIN=1`, `VELTRITE_WINDOWS_PUBLISHER` (имя издателя сертификата) | `WINDOWS_CERTIFICATE_P12` (base64 P12), `WINDOWS_CERTIFICATE_PASSWORD` |

Временный P8 создаётся в папке CI с ограниченными правами и удаляется на завершающем шаге, в том числе при ошибке. electron-builder импортирует сертификат Mac во временную связку ключей. Сертификаты не передаются тестовому приложению. После подключения сертификатов нужно отдельно пройти приёмку подписи, нотарификации и обновления подписанной версии.

## Нативная приёмка

Workflow проверяет ARM64 Mac, Intel Mac и Windows на соответствующих системах. Mac: монтирование DMG только для чтения, копирование в временную «Applications», проверка целостности подписи, запуск и сценарии Electron. Windows: установка опубликованной 0.2.1 с проверкой SHA-256, обновление до текущей версии, сценарии установленного приложения, загрузка и реальная установка отдельного тестового кандидата через localhost, удаление с проверкой сохранности синтетических заметок и профиля. Кандидат имеет отдельную тестовую версию и не публикуется.

Все профили, заметки, кэши и отчёты создаются вне исходников. Проверка Windows разрешена только на одноразовом CI-агенте; текущая пользовательская установка не используется.
